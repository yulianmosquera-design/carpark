1. INTRODUCCIÓN

El sistema de información del parqueadero comercial "Autos Colombia" avanza en su ciclo de vida con la ejecución de la Iteración 2, centrada específicamente en la Gestión de Usuarios y la Gestión Avanzada de Celdas, manteniendo total cohesión y compatibilidad operativa con la Iteración 1 (Gestión de la entrada y salida de vehículos).

La administración física y de seguridad de un parqueadero de alta rotación requiere mecanismos formales de control de acceso basados en roles (RBAC: Administrador, Operador y Auditor/Supervisor), así como herramientas interactivas de zonificación, parametrización de celdas por tipo de automotor, inhabilitación por mantenimiento y la capacidad crítica de reasignación atómica de celdas, la cual permite trasladar vehículos en estadía activa preservando la integridad del ticket y de las tarifas.

2. OBJETIVOS DE LA ITERACIÓN 2

2.1 Objetivo General

Diseñar, modelar, validar e implementar los módulos de Gestión de Usuarios y Gestión de Celdas para el parqueadero "Autos Colombia", garantizando la integridad referencial, transaccionalidad ACID y trazabilidad de operaciones.

2.2 Objetivos Específicos

  • Levantar y documentar formalmente los Requerimientos Funcionales (RF) y No Funcionales (RNF) para usuarios y celdas.
  • Modelar los Diagramas de Casos de Uso, Diagramas de Secuencia transaccionales y el Diagrama de Componentes arquitectónico en StarUML (UML 2.2).
  • Definir las Historias de Usuario con criterios de aceptación Gherkin (Given-When-Then).
  • Diseñar mockups de alta fidelidad bajo el tema oscuro profesional CarPark con paleta de acentos Rojo (#FF0000) y Oro (#D4AF37).
  • Estructurar y diligenciar el Formato de Plan de Pruebas Resumido, respaldado por una suite automatizada de 21 pruebas con el 100% de éxito.
  • Sincronizar y evidenciar la actualización del código fuente en el repositorio GitHub oficial.

3. REQUERIMIENTOS FUNCIONALES Y NO FUNCIONALES

3.1 Requerimientos Funcionales de Gestión de Usuarios (RF-USU)

  • RF-USU-01 (Registro de Usuarios): El sistema debe permitir registrar usuarios capturando documento, username único, contraseña encriptada, nombres, apellidos, teléfono, correo y rol del sistema.
  • RF-USU-02 (Control de Acceso RBAC): El sistema debe diferenciar privilegios entre perfiles Administrador, Operador y Auditor/Supervisor.
  • RF-USU-03 (Edición de Usuarios): El sistema debe permitir actualizar datos de contacto y roles sin comprometer el identificador primario.
  • RF-USU-04 (Desactivación Lógica): El sistema debe permitir inhabilitar usuarios cambiando su estado a INACTIVO, preservando el histórico de auditoría sin borrado físico en base de datos.
  • RF-USU-05 (Trazabilidad de Turnos): Cada transacción de entrada, salida, cobro o novedad debe registrar el operador responsable.

3.2 Requerimientos Funcionales de Gestión de Celdas (RF-CEL)

  • RF-CEL-01 (Parametrización de Celdas): El sistema debe permitir crear celdas asignando código único, piso/zona física y tipo de vehículo admitido.
  • RF-CEL-02 (Mapa Gráfico en Tiempo Real): El sistema debe renderizar el mapa de celdas por zonas con código cromático (Verde: Disponible, Rojo: Ocupada, Oro: Mantenimiento).
  • RF-CEL-03 (Bloqueo por Mantenimiento): El sistema debe permitir inhabilitar celdas por reparaciones o aseo, impidiendo su asignación a nuevos vehículos.
  • RF-CEL-04 (Reasignación Atómica de Celdas): El sistema debe transferir un vehículo estacionado de una celda ocupada a otra disponible mediante una transacción atómica que mantenga el ticket y la hora de entrada.
  • RF-CEL-05 (Métricas de Distribución): El sistema debe calcular porcentajes de ocupación y balance de espacios libres en el Dashboard ejecutivo.

3.3 Requerimientos No Funcionales (RNF)

  • RNF-01 (Rendimiento): El tiempo de consulta y renderizado del mapa de celdas y usuarios debe ser inferior a 800 ms (medición real obtenida: 1.41 ms).
  • RNF-02 (Concurrencia ACID): Las reasignaciones deben ejecutarse bajo transacciones serializables en SQLite para evitar colisiones.
  • RNF-03 (Seguridad): Contraseñas resguardadas con algoritmos de hashing seguro e inyección de datos prevenida mediante Prepared Statements.

5. HISTORIAS DE USUARIO CON CRITERIOS GHERKIN

Historia de Usuario HU-USU-01: Alta de Nuevo Operador

Como: Administrador del parqueadero Autos Colombia
Quiero: Registrar a un nuevo empleado con sus datos y perfil operativo
Para: Concederle acceso al sistema y asignar responsabilidades trazables en los turnos.

Escenario: Registro exitoso de operador con datos válidos
  Dado que el Administrador ha ingresado al módulo de usuarios
  Cuando completa el documento "1098765432", username "carlos_turnoa", rol "Operador" y contraseña válida
  Y presiona "Guardar Usuario"
  Entonces el sistema registra al usuario con estado "ACTIVO"
  Y muestra el mensaje "Usuario creado exitosamente"
  Y el nuevo operador aparece en el listado general.

Escenario: Intento de registro con username duplicado
  Dado que ya existe un usuario con el nombre de usuario "carlos_turnoa"
  Cuando el Administrador intenta crear otro usuario con el mismo username "carlos_turnoa"
  Entonces el sistema bloquea la inserción
  Y responde con el error "El nombre de usuario ya se encuentra en uso".

Historia de Usuario HU-CEL-02: Reasignación Atómica de Celdas

Como: Operador de parqueadero
Quiero: Cambiar la celda asignada a un vehículo estacionado sin alterar su cobro ni su ticket
Para: Reubicar el carro por reorganización interna o ingreso de celda a mantenimiento.

Escenario: Reasignación exitosa de celda compatible
  Dado un automóvil con placa "ABC123" ubicado en la celda "A-04" (OCUPADA)
  Y una celda "A-03" en estado "DISPONIBLE" para tipo Automóvil
  Cuando el Operador ejecuta la reasignación de "A-04" hacia "A-03"
  Entonces la celda "A-04" cambia a estado "DISPONIBLE"
  Y la celda "A-03" pasa a estado "OCUPADA" con la placa "ABC123"
  Y el registro de estadía conserva intacto el ticket, la hora de entrada y el cálculo de tarifa.

11. CONCLUSIONES

  1. Arquitectura Escalable y Mantenible: La estructuración modular por capas permitió incorporar la gestión de usuarios y celdas sin regresiones en las funcionalidades previas de entrada y salida de vehículos.
  2. Integridad y Control Operativo: La reasignación atómica de celdas y la desactivación lógica de usuarios resuelven contingencias cotidianas del parqueadero sin vulnerar la trazabilidad financiera ni histórica.
  3. Confiabilidad Respaldada en Pruebas: La suite de pruebas de software automatizadas certificó un 100% de efectividad en los 21 casos evaluados, asegurando tiempos de respuesta óptimos (1.41 ms) y resistencia ante datos duplicados o inconsistentes.
